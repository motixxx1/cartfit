# CartFit · סל-פיקס 🛒

סל קניות חכם שנבנה **בדיוק** לפי התקציב — בכל רשת סופרמרקט בישראל.

> סליידר תקציב → האלגוריתם ממלא סל מאוזן שנוגע ב-98%-100% מהתקציב מבלי לחרוג ממנו.
> מצב שף → בוחרים מנה ומספר סועדים ומקבלים כמויות מדויקות, מוצרי מדף אמיתיים ומדריך הכנה.

## שלושה דליברבלים נפרדים

| | מה זה | איפה | תלוי בשאר? |
|---|---|---|---|
| 📱 **אפליקציה** | APK לאנדרואיד | [Releases](../../releases) | **לא** — הקטלוג והאלגוריתמים בתוך ה-APK |
| 🖥️ **אתר** | אתר סטטי | GitHub Pages | לא — רץ בדפדפן, אותו קוד לקוח |
| ⚙️ **שרת** | FastAPI + Docker | `ghcr.io/<owner>/cartfit/api` | לא — API עצמאי לקליטת מחירים אמיתיים |

שלושתם חולקים קוד אבל נפרסים לחוד. הלקוח מחשב הכול מקומית כברירת מחדל; הגדרת
`NEXT_PUBLIC_API_URL` מפנה אותו לשרת, והמנוע המקומי נשאר כגיבוי כשאין רשת.

### 📱 להתקין את האפליקציה

1. [Releases](../../releases) → להוריד את `cartfit-<גרסה>.apk`.
2. לפתוח את הקובץ בטלפון ולאשר התקנה ממקור לא מזוהה.
3. זהו. אין הרשמה, אין שרת, עובד גם בלי קליטה בסניף.

ה-APK חתום במפתח debug — מתאים להתקנה ישירה, לא להפצה בחנות.
לבנות גרסה חדשה: לדחוף תג `v*`, או להריץ ידנית את ה-workflow **Android APK** עם שם תג.

## הרצה מקומית

```bash
# שרת (http://localhost:8000/docs)
cd backend && pip install -r requirements-dev.txt && uvicorn app.main:app --reload

# לקוח (http://localhost:3000) — ללא שרת כברירת מחדל
cd frontend && npm install && npm run dev

# לחבר את הלקוח לשרת
echo "NEXT_PUBLIC_API_URL=http://localhost:8000" > frontend/.env.local
```

בניית APK מקומית דורשת Android SDK + JDK 17:

```bash
cd frontend
npm run build && npx cap sync android
cd android && ./gradlew assembleDebug      # app/build/outputs/apk/debug/
```

## ⚙️ להריץ את השרת

השרת עצמאי לגמרי — האפליקציה והאתר עובדים בלעדיו. הוא נחוץ כשרוצים מחירים
אמיתיים מקבצי חוק המזון במקום קטלוג הדמו.

```bash
# מקומית
docker compose up -d                 # http://localhost:8000/docs

# או מהאימג' ש-CI מפרסם
docker run -d -p 8000:8000 -v cartfit-data:/data \
  ghcr.io/motixxx1/cartfit/api:main
```

**לענן:** `backend/render.yaml` (Render → New → Blueprint) או `backend/fly.toml`
(`fly launch --copy-config`). שניהם מגדירים דיסק ב-`/data`, בדיקת בריאות ב-`/health`
ואזור אירופאי.

| משתנה סביבה | ברירת מחדל | למה |
|---|---|---|
| `PORT` | `8000` | פורט ההאזנה |
| `DATABASE_URL` | `sqlite:///./cartfit.db` | `sqlite:////data/cartfit.db` לדיסק מחובר |
| `CORS_ORIGINS` | `*` | רשימה מופרדת בפסיקים של דומיינים מורשים |

**לחבר את הלקוח לשרת:** Settings → Secrets and variables → Actions → Variables →
`CARTFIT_API_URL` עם כתובת השרת. ה-workflow של האתר בונה מולו, והמנוע המקומי
נשאר כגיבוי כשאין רשת. ה-APK נשאר אופליין בכוונה.

## האלגוריתמים

### 1. Knapsack לפי תקציב

התקציב מחולק לקטגוריות לפי סוג הסל:

| מיקוד | טרי | חלבון | יבש | חטיפים | נלווים |
|---|---|---|---|---|---|
| `balanced` | 35% | 25% | 20% | 10% | 10% |
| `pantry` | 20% | 15% | 40% | 10% | 15% |
| `weekend` | 30% | 35% | 10% | 18% | 7% |

לכל קטגוריה נפתר **Multiple-Choice Knapsack** בתכנון דינמי: לכל מוצר יש אפשרות
"יחידה אחת" ואפשרות "מארז מבצע" (`3 ב-25 ₪`), והאלגוריתם בוחר לכל היותר אחת מהן.
פונקציית התועלת מתגמלת על מוצרי יסוד, אחוז ההנחה, התאמה לחג/עונה, ציון בריאות
ומוצרים ממומנים (מתויגים "ממומן" בממשק). רזולוציית ה-DP מתכווננת לפי גודל התקציב
(10/25/50 אגורות) כדי לשמור על זמן ריצה של מילישניות.

לסגירת התקציב רצים שני מעברים: **greedy filler** של פריטים קטנים, ואז **top-up**
שמגדיל כמות של מוצרי יסוד כשהקטלוג מיצה את עצמו. פריטים נעולים 🔒 נשמרים בין
ערבובים.

### 2. מנוע ארוחות

```
servings = adults + kids × 0.6
```

כל רכיב מוגדר כ-`per_person` + `tag`; המנוע בוחר את ה-SKU המשתלם ביותר לפי מחיר
ל-100 גרם (כולל מבצעים) ומתרגם גרמים → מארזים קמעונאיים (`ceil` עם סובלנות 7%).
"יש לי בבית" מוציא תבלינים ושמן מהסל.

### 3. צינור מחירים ישראלי

`xml_parser.py` קורא `PriceFull / Price / PromoFull / Promo` (XML ב-GZ), מנרמל
`ItemCode` ל-GTIN-13 ומתאים לקטלוג לפי ברקוד. מכיר שמות שדות חלופיים בין הרשתות
ותגיות `ClubId` לחישוב הנחות מועדון רק לזכאים. כתובות הפורטלים: `GET /api/prices/sources`.

## נתוני הדמו

93 מוצרים ישראליים עם ברקודי GTIN-13 תקינים, מחירים נפרדים ל-5 רשתות, 92 מבצעים
(44 מועדון), 44 מבצעי כמות, ערכים תזונתיים וסימוני אזהרה של משרד הבריאות, תאריכי
תפוגה ותגיות חג/עונה/כשר-לפסח.

> המחירים הם דמו מציאותי. בייצור הם נדרסים מקבצי חוק המזון דרך `POST /api/prices/ingest`.

**מגבלת קטלוג ידועה:** בתקציב גדול הסל מכיל רוב הקטלוג, ולכן "החלף מוצר" מדווח
שכל החלופות כבר בסל. זה נעלם עם קליטת קטלוג אמיתי.

## מה עוד חסר לייצור

- **אימות משתמשים** — כל המצב כרגע לפי מכשיר (`user_id="demo"` בשרת).
- **מחיר לסניף** — קבצי חוק המזון הם per-`StoreId`; המודל מחזיק מחיר אחד לרשת.
- **מסד נתונים** — הקטלוג בזיכרון, קליטת מחירים לא שורדת restart. צריך Postgres.
- **מוצרי מותג פרטי** — ברקוד פנימי לכל רשת, לא ניתן להשוואה לפי GTIN.
- **OCR לקבלות** — השרת מקבל טקסט; צריך Vision/Tesseract בצד הלקוח.
- **התראות Push** — הלוגיקה מחזירה אובייקטי התראה מוכנים; צריך FCM.
- **מבצעי סף סל** ("קנה ב-100 קבל X") — נבנו רק מבצעי `N ב-מחיר`.
- **מוצרים במשקל** — `ItemType` נקרא מה-XML ולא בשימוש.
- **גילוי נאות** — עמלות אפיליאייט, דיוק מחירים ופרטיות צילומי קבלות.
